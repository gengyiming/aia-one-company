## B. 关键问题诊断

### P0 — 系统性缺陷（必须立即修复）

| ID | 问题 | 现状 | 后果 |
|----|------|------|------|
| P0-1 | **CEO 单一入口不是硬规则** | 根目录 CLAUDE.md 写"用户 cd 到部门目录自动切换"，可绕过 CEO | 部门指令不经 CEO 过滤，与全局优先级冲突；任务不留痕，无法追溯 |
| P0-2 | **CEO 没有结构化记忆系统** | 无"用户画像/偏好/风格"的持久记忆文件 | 每次新会话从零理解用户；"越用越懂"无从实现 |

### P1 — 流程断裂（影响闭环质量）

| ID | 问题 | 现状 | 后果 |
|----|------|------|------|
| P1-1 | **任务完成后无结构化复盘** | 任务 `done` 后直接结束，无验收→反馈→回写记忆的闭环 | 同样错误反复；用户偏好无处沉淀 |
| P1-2 | **分派缺少预检** | 无"该不该派？派给谁？输入够不够？"的预检清单 | 无效任务、派错部门、信息不全 |
| P1-3 | **OKR/复盘/决策日志全空** | 三个文件均为纯模板 | CEO 做决策无历史参考，目标追踪形同虚设 |

### P2 — 治理漏洞（可后期修补）

| ID | 问题 | 现状 | 后果 |
|----|------|------|------|
| P2-1 | **部门间协作缺 CEO 可见性** | 存在 `content_marketing→business_dev` 的任务，CEO 不在 from_agent | 无主动通知/审批，可能优先级冲突 |
| P2-2 | **无部门能力矩阵** | CEO 分派靠经验，无"哪类任务归谁"映射 | 新任务类型分派可能错配 |
| P2-3 | **Claude Code memory 与 Vault 记忆无关联** | 两套记忆各自独立 | 跨会话记忆断裂 |

### C2. 单次交互完整流转

```
用户输入
  │
  ▼
CEO Agent 接收
  │
  ├─ 1. 读取 [[00-ceo/ceo-memory/用户画像]]     ← 每次会话开头
  ├─ 2. 读取 [[00-ceo/ceo-memory/决策偏好]]     ← 校准沟通风格
  ├─ 3. 意图识别（5类路由，见 C3）
  │
  ├─ 若「知识问答」→ CEO直接答 + 知识回写SOP + 捕捉偏好
  ├─ 若「闲聊/确认」→ CEO直接答 + 捕捉隐含偏好
  ├─ 若「信息查询」→ CEO读取看板/文件直接答
  │
  ├─ 若「任务指令」→ 进入分派流程：
  │   ├─ a. 查 [[00-ceo/ceo-memory/分派经验]]（有匹配规则？）
  │   ├─ b. 查 [[_agent-system/部门能力矩阵]]（路由到谁？）
  │   ├─ c. 走 [[_agent-system/intake/任务分派预检SOP]]（5项全过）
  │   ├─ d. 向用户展示分派摘要 → 用户确认
  │   ├─ e. 创建任务单 → _agent-system/tasks/
  │   └─ f. 部门执行（CEO跟踪状态）
  │
  └─ 若「复盘/决策」→ 汇总数据 → 写入周复盘/决策日志/OKR

部门完成 → status: done → CEO 走 [[_agent-system/intake/任务复盘SOP]]
  │
  ├─ 验收交付物
  ├─ 采集用户反馈
  ├─ 提炼经验 → 回写4个记忆文件
  └─ 通知用户结果
```

### C3. 意图识别决策树

```
用户输入 →

类型1: 知识问答
  信号词：为什么/怎么做/什么是/如何比较/有哪些/适合谁
  → CEO 直接回答 + 知识回写 SOP
  → 若专业深度超CEO范围 → 读取对应部门 knowledge/ 辅助

类型2: 任务指令
  信号词：帮我做/创建/分析/整理/跟进/生成/出一份
  → 走分派预检 SOP → 创建任务单 → 分派

类型3: 信息查询
  信号词：目前/进度/状态/有多少/怎么样了
  → CEO 读取 inbox/Pipeline/OKR/记忆文件 直接回答

类型4: 复盘与决策
  信号词：复盘/总结/回顾/决定/选择/对比方案
  → 走复盘流程或决策分析流程

类型5: 闲聊与确认
  → CEO 直接回应 + 捕捉隐含偏好更新记忆
```

   - [ ] 主执行部门已明确？（查部门能力矩阵）

   - [ ] 交付标准可量化（>=2 条 checklist）？
   - [ ] 截止日期合理（考虑部门负载）？

#### D2.3 复盘 SOP（5 步）

  - 若 review_score = low → 自动创建改进任务

## E. CEO 记忆系统设计

### E1. 文件结构

```
00-ceo/ceo-memory/
├── 用户画像.md         ← 用户是谁、偏好什么、忌讳什么
├── 决策偏好.md         ← 用户做决策时的规律性模式
├── 分派经验.md         ← 哪类任务怎么分效果最好
├── 反馈记录.md         ← 用户对交付结果的满意度
└── archive/            ← 季度归档
    └── YYYY-QX-摘要.md
```

### E2. 各文件字段规范

#### 用户画像.md

| 字段块 | 记录格式 | 示例 |
|--------|----------|------|
| 基本信息 | `- 键：值` | `- 角色：AIA HK 理财顾问` |
| 工作偏好 | `- [偏好] (来源: YYYY-MM-DD 对话/任务)` | `- 偏好先出方案再讨论细节 (来源: 2026-03-04)` |
| 沟通风格 | `- [观察] (来源: YYYY-MM-DD)` | `- 喜欢中英混合 (来源: 2026-03-04)` |
| 约束与红线 | `- [约束] (来源: YYYY-MM-DD)` | `- 不做返佣/回扣 (来源: 2026-03-05)` |
| 当前关注重点 | `- [重点] (来源: YYYY-MM-DD) — 有效期至 YYYY-MM-DD` | `- 投资移民 — 有效期至 2026-04-30` |
| 更新日志 | `### YYYY-MM-DD — 摘要` | `### 2026-03-04 — 首次建档` |

#### 决策偏好.md

| 字段块 | 记录格式 | 示例 |
|--------|----------|------|
| 风险偏好 | 自由文本 | `偏好稳健方案，对高波动产品谨慎` |
| 时间偏好 | 自由文本 | `喜欢快速出初版，迭代优化` |
| 信息偏好 | 自由文本 | `偏好一页摘要+数据支撑` |
| 审批偏好 | 自由文本 | `high 优先级需确认，其余可自动` |
| 已确认决策规则 | `- 规则 (来源: YYYY-MM-DD，场景)` | `- 产品对比至少含3款 (来源: 2026-03-05)` |

#### 分派经验.md

| 字段块 | 记录格式 |
|--------|----------|
| 分派规则（已验证） | `### 场景：[类型]` + `最佳分派/需cc/关键输入/注意/来源` |
| 常见失败模式 | `- [失败] → 改进措施 (来源: task_id)` |

#### 反馈记录.md

| 字段块 | 记录格式 |
|--------|----------|
| 反馈条目 | `### YYYY-MM-DD — [task_id]` + `满意度/反馈/改进/已回写位置` |

### E3. 更新节奏

| 更新时机 | 频率 | 触发方式 | 写入目标 |
|----------|------|----------|----------|
| 对话中发现偏好 | 每次对话 | CEO 自动捕捉 | 用户画像.md |
| 用户做出选择 | 每次决策 | 决策过程中提炼 | 决策偏好.md |
| 用户表达满意/不满 | 实时 | 语义识别 | 反馈记录.md |
| 任务完成复盘 | 每次 done | 复盘 SOP | 分派经验.md + 反馈记录.md |
| 周复盘整理 | 每周 1 次 | 周复盘流程 | 用户画像.md「当前关注重点」 |
| 月度深度整理 | 每月 1 次 | 记忆维护 SOP | 全部 4 文件 |
| 季度归档 | 每季 1 次 | 记忆维护 SOP | archive/ + 主文件精简 |

### E4. 冲突处理规则

| 冲突类型 | 处理方式 |
|----------|----------|
| 新信息与旧记忆矛盾 | 两条保留，新条目标注 `[待确认-与YYYY-MM-DD条目矛盾]`，下次对话求证 |
| 用户口头修正旧偏好 | 旧条目标 `[已过时-YYYY-MM-DD]`，新条目写入，更新日志记录 |
| 不同场景下偏好不同 | 用场景限定词区分，如 `大单偏好详细方案` vs `小单偏好快速推荐` |
| 用户说"忘掉之前说的" | 对应条目删除，更新日志记录"应用户要求删除XXX" |

### E5. 版本化

- 每个记忆文件 frontmatter 含 `version: N`（整数，每次更新 +1）和 `updated: YYYY-MM-DD`
- 更新日志段落记录每次变更摘要
- 季度归档时 version 不重置，持续累加
- 归档文件命名：`archive/YYYY-QX-摘要.md`，含该季度 version 起止范围

## F. 任务治理

### F1. 任务单模板新增字段

```yaml
# === 新增字段 ===
precheck_passed: false       # 分派预检是否通过
okr_alignment: ""            # 对齐的 OKR（如 O1-KR2）
review_score: ""             # 满意度: high/medium/low
review_notes: ""             # 反馈摘要
memory_updated: false        # 是否已回写CEO记忆
completion_date: ""          # 实际完成日期
```

### F2. 分派规则

| 规则 | 说明 |
|------|------|
| **CEO 唯一发起** | 所有任务 `from_agent` 必须为 `ceo`；部门间协作 `cc_agents` 含 `ceo` |
| **预检前置** | 创建前必须通过 13 项预检，`precheck_passed: true` |
| **OKR 对齐** | 每个任务必填 `okr_alignment`，无法关联需说明理由 |
| **用户确认** | high 优先级必须用户确认分派摘要；medium/low 可自动但需告知 |
| **负载均衡** | 单部门超 5 个未完成任务时预警 |

### F3. 升级规则

| 等级 | 触发条件 | CEO 动作 |
|------|----------|----------|
| L0 正常 | due 前完成 + review_score=high | 正常关闭，提取正面经验 |
| L1 关注 | 距 due <=2 天仍 in_progress | 提醒用户，询问调整 |
| L2 预警 | blocked 超 2 天 | 诊断阻塞，提出 unblock 方案 |
| L3 升级 | 连续 2 次 low（同部门） | 触发系统改进任务 |
| L4 系统级 | 用户说"系统不好用" | 暂停执行，全面复盘架构 |

### F4. 验收规则

| 步骤 | 执行者 | 动作 |
|------|--------|------|
| 1. 交付检查 | CEO | 逐条核对交付标准 + 打开 deliverable 确认存在 |
| 2. 不达标 | CEO | status 改回 in_progress，写明缺什么 |
| 3. 用户反馈 | CEO→用户 | 简报结果 + 询问满意度 |
| 4. 复盘回写 | CEO | 走复盘 SOP 全 5 步 |
| 5. 正式关闭 | CEO | review_score + review_notes + memory_updated 全填 |
