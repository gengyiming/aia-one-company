# PDF 结构化解析策略库（逻辑驱动）

目标：不同 PDF 使用不同解析框架，避免“统一模板化输出”导致信息失真。

## 总原则

1. 先识别文档逻辑，再决定输出结构。
2. 正文结构跟随原文目录与论证顺序，不强制统一章节。
3. 摘要文件是“决策视图”，全量文件是“证据视图”，两者必须互链。
4. 每个关键结论都要有页码证据。

## 文档逻辑类型与建议框架

### `policy`（政策/规则/指南）

适用：监管规则、资格政策、制度指南。  
建议结构：
1. 版本信息与适用范围
2. 资格/定义体系
3. 流程与时限
4. 关键限制与边界
5. 版本差异与变更点
6. 执行影响（业务/客服/内容/数据）

### `product`（产品资料）

适用：产品册子、一页纸、说明书。  
建议结构：
1. 产品定位与目标客群
2. 利益结构与触发条件
3. 关键时间点（提取/转换/锁定/生效）
4. 限制与不适用情形
5. 非保证与风险提示
6. 话术落地与产品卡回写点

### `contract`（合同/条款）

适用：保单条款、协议文本、法律约定。  
建议结构：
1. 定义与解释优先级
2. 权利义务矩阵（甲/乙方）
3. 触发条件与终止条件
4. 免责与除外责任
5. 争议处理与管辖
6. 生效、续期、变更机制

### `report`（研究/分析报告）

适用：行业报告、经营分析、调研报告。  
建议结构：
1. 研究问题与方法
2. 数据来源与样本边界
3. 关键发现与证据
4. 假设条件与局限性
5. 结论与行动建议
6. 指标落地与监控方案

### `presentation`（PPT/提案）

适用：演示文稿、销售提案、路演材料。  
建议结构：
1. 主张链路（问题 -> 方案 -> 价值）
2. 核心论点与支撑页
3. 假设与前提
4. 可执行动作与时间线
5. 风险点与反驳准备

### `mixed`（混合型）

适用：一个文件混合政策+产品+流程。  
建议结构：
1. 先拆块（按逻辑块分组）
2. 各块采用对应策略
3. 最后汇总跨块冲突与统一结论

## 最小治理要求（固定）

不固定正文模板，但必须满足：
- frontmatter 完整（含 `document_logic_type`）
- 任务回链、来源回链、回写位置
- 全量逐页文件回链
- 分派建议明确到部门
